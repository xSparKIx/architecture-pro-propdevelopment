# Требования к внешним интеграциям PropDevelopment

## 1. Требования к безопасности

### 1.1. Шифрование данных

#### Обязательные требования:

- Все внешние соединения должны использовать TLS 1.2+
- Шифрование данных в rest с использованием AES-256-GCM
- Обязательная проверка SSL-сертификатов
- Хранение чувствительных данных только в зашифрованном виде

### 1.2. Контроль доступа

- Реализация принципа минимальных привилегий
- Обязательная MFA (двухфакторная аутентификация) для административного доступа
- Сегментация сетевого доступа между зонами доверия
- Регулярный аудит прав доступа (ежеквартально)

### 1.3. Защита API

- Валидация всех входящих данных (JSON Schema)
- Ограничение размера payload (max 10MB)
- Защита от OWASP Top 10 уязвимостей
- Rate limiting по типам клиентов

## 2. Протоколы аутентификации и авторизации
### 2.1. Аутентификация
#### Основные протоколы:

***OAuth 2.0 / OpenID Connect:***
  - Для пользовательской аутентификации
  - Grant types: Authorization Code, Client Credentials
  - Использование PKCE для публичных клиентов

***API Key + Signature:***
  - Для B2B интеграций
  - HMAC-SHA256 подпись запросов
  - Временные токены (max 1 час)

***mTLS (Mutual TLS):***
  - Для высоко-безопасных интеграций
  - Государственные системы
  - Финансовые провайдеры

### 2.2. Авторизация

#### RBAC (Role-Based Access Control):

***Роли:***
  - customer: чтение своих данных
  - tenant: управление ЖКУ, платежи
  - partner: доступ к API партнёра
  - admin: полный доступ

***Scope-based доступ:***
  - read:profile - чтение профиля
  - write:payments - создание платежей
  - read:meter_data - показания счетчиков
  - write:notifications - отправка уведомлений

### 2.3. Управление токенами

- Время жизни access token: 15 минут
- Время жизни refresh token: 7 дней
- Автоматическая инвалидация при смене пароля
- Blacklist скомпрометированных токенов

## 3. Организация взаимодействия между системами
### 3.1. Архитектурный подход
#### API Gateway как единая точка входа:

```
Внешние клиенты → API Gateway → Внутренние сервисы
```

***Преимущества:***

- Единая точка аутентификации
- Централизованный мониторинг
- Упрощение клиентских интеграций
- Единый контроль доступа

### 3.2. Паттерны интеграции
#### 3.2.1. Синхронное взаимодействие (REST/gRPC)
Для:

- Операций требующих немедленного ответа
- Пользовательских действий в реальном времени
- Проверки доступности услуг

#### 3.2.2. Асинхронное взаимодействие (Message Queue)

Для:

- Обработки длительных операций
- Массовых уведомлений (мониторинга итд.)
- Синхронизации данных
- Обработки платежей

### 3.3. Специфические требования по типам интеграций
#### 3.3.1. Поставщики ЖКХ

```
Протокол: REST API / SOAP
Аутентификация: OAuth 2.0 Client Credentials
Частота обновления: ежедневно (00:00-06:00)
Данные:
  - Тарифы и начисления
  - Показания счетчиков
  - Информация об отключениях
```

#### 3.3.2. Платёжные системы

```
Протокол: REST API Webhooks
Аутентификация: mTLS + JWT
Требования:
  - Подтверждение платежа в течение 5 секунд
  - Idempotency key для предотвращения дублей
  - Webhook retry policy (3 попытки, экспоненциальная backoff)
```

#### 3.3.3. IoT устройства (умный дом)

```
Протокол: MQTT over TLS + REST API
Аутентификация: X.509 certificates + JWT
Требования:
  - Keep-alive: 60 секунд
  - QoS: 1 (at least once)
  - Topics segmentation по клиентам
```

#### 3.3.4. Государственные системы (СМЭВ)
```
Протокол: SOAP + WS-Security
Аутентификация: mTLS + XML Signature
Требования:
  - Соответствие ФЗ-152 (персональные данные)
  - Логирование всех операций (5 лет)
  - Межсетевое экранирование
```
