# Проверочный лист по информационной безопасности PropDevelopment

| **I. Управление доступом** | | | |
| 1 | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | Нет | Критически важно для защиты финансовых и персональных данных |
| 2 | Настроены ли требования к сложности паролей и их регулярное обновление? | Нет | Базовый контроль, отсутствие которого усугубляет проблемы с контролем данных |
| 3 | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | Нет | Прямо влияет на решение проблемы нарушения контроля данных |
| 4 | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Нет | Ключевая мера для предотвращения доступа пользователей к чужим данным |
| 5 | Автоматически ли удаляются или деактивируются учётные записи после увольнения или изменения должности сотрудников? | Нет | Снижает риск утечки данных через "зомби"-аккаунты |
| 6 | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | Нет | Необходимо для расследования инцидентов, связанных с утечкой |
| 7 | Используются ли механизмы контроля доступа на основе атрибутов для повышения гибкости управления доступом? | Нет | Позволяет реализовать более тонкие политики доступа |
| 8 | Используются ли системы аутентификации пользователей для доступа к системам? | Да | Базовый контроль присутствует, но его недостаточно |
| 9 | Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными? | Нет | Прямое решение для изоляции финансовых и персональных данных |
| 10 | Ограничен ли доступ к системам из внешних источников? | Нет | Расширяет поверхность атаки |
| 11 | Ведётся ли единый реестр учётных записей? | Да | Положительный фактор, основа для построения контроля |
| 12 | Используются ли средства управления учётными записями на базе единого реестра? | Да | Положительный фактор |
| 13 | Применяются ли средства для отзыва прав доступа? | Да | Положительный фактор |
| 14 | Используются ли средства централизованного контроля доступа? | Нет | Отсутствие централизованного контроля усугубляет проблемы |
| **II. Безопасность данных** | | | |
| 1 | Разработана ли политика классификации данных, и актуализируется ли она в соответствии с действующим законодательством? | Нет | Фундаментальный пробел. Без классификации невозможно выстроить адекватную защиту |
| 2 | Используется ли шифрование на уровне базы данных, файловой системы и при передаче данных по сети? | Нет | Критический риск для конфиденциальных и секретных данных. Требование стандартов PCI DSS и 152-ФЗ |
| 3 | Реализованы ли механизмы управления ключами шифрования? | Неизвестно | Без этого даже внедрённое шифрование будет небезопасным |
| 4 | Проводится ли регулярное резервное копирование данных? Хранятся ли резервные копии в защищённых хранилищах? | Да | Положительный фактор |
| 5 | Выполняется ли регулярное тестирование процесса восстановления данных из резервных копий? | Неизвестно | Резервные копии бесполезны, если восстановление не работает |
| 6 | Ограничен ли доступ к резервным копиям данных, и зашифрованы ли они? | Неизвестно | Резервные копии — частый вектор атак |
| 7 | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных? | Неизвестно | Требование законодательства (152-ФЗ). Необходимо уточнить |
| 8 | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности для маркировки данных? | Нет | Невозможно без внедренной классификации данных |
| 9 | Разработаны ли процессы и системы Data Governance для управления данными? | Нет | Системная проблема, ведущая к нарушению контроля данных |
| 10 | Реализованы ли системы или процессы безопасного уничтожения данных? | Неизвестно | Необходимо для соблюдения законодательства |
| 11 | Используются ли системы или процессы контроля целостности данных? | Неизвестно | Важно для предотвращения искажения финансовой информации и данных умного дома |
| 12 | Реализованы ли системы или процессы контроля сохранности данных? | Неизвестно | Прямо связано с риском потери данных |
| 13 | Применяются ли средства или процессы анонимизации данных? | Неизвестно | Может требоваться для процессов разработки и аналитики |
| 14 | Разработана ли инструкция по процессу восстановления данных? | Неизвестно | Критически важно для минимизации ущерба от инцидентов |

| 3 | Используются ли IDS/IPS-системы для обнаружения и предотвращения сетевых атак? | Неизвестно | Ключевой контроль для выявления сложных атак |
| 4 | Настроен ли мониторинг сетевого трафика на предмет аномалий и возможных атак, например, DDoS? | Неизвестно | Защита от атак на доступность сервисов |
| 5 | Проводится ли регулярное сканирование уязвимостей операционных систем, приложений и сетевых устройств? | Неизвестно | Проактивное выявление и устранение слабых мест |
| 6 | Установлены ли на серверах и рабочих станциях антивирусные программы и системы EDR? | Неизвестно | EDR особенно важен для обнаружения атак в корпоративной сети |
| 7 | Отключены ли неиспользуемые службы и порты на серверах, рабочих станциях и сетевом оборудовании? | Неизвестно | Снижает поверхность атаки. Стандартная практика харденинга |
| 8 | Используются ли механизмы контроля целостности системных файлов? Ведётся ли журналирование доступа к системным ресурсам? | Неизвестно | Помогает обнаружить несанкционированные изменения |
| 9 | Проводятся ли автоматизированные сканирования облачных инфраструктур на соответствие рекомендациям безопасности? | Неизвестно | Особенно актуально для приватного облака компании |
| 10 | Реализовано ли автоматическое обновление сигнатур защиты от вредоносных программ? | Неизвестно | Обеспечивает актуальную защиту |
| 11 | Осуществляется ли фильтрация трафика между сетевыми сегментами? | Неизвестно | Важная часть сетевой сегментации |
| 12 | Используются ли средства для контроля периметра доступа? | Неизвестно | Дополнительный контроль для ЦОД |
| **IV. Управление инцидентами** | | | |
| 1 | Используется ли система мониторинга безопасности (SIEM) для корреляции событий и анализа аномалий в режиме реального времени? | Нет | Без SIEM реакция на инциденты запаздывает |
| 2 | Настроены ли автоматические оповещения об инцидентами и подозрительной активности (например, попытках несанкционированного доступа)? | Нет | Невозможно без системы мониторинга |
| 3 | Разработан ли план реагирования на инциденты, включающий анализ, эскалацию и восстановление системы? Проводится ли обучение сотрудников? | Нет | Компания не готова к реагированию на инциденты |
| 4 | Проводятся ли симуляции инцидентов (учения) для проверки готовности сотрудников к реагированию на кибератаки? | Нет | План реагирования должен регулярно отрабатываться |
| 5 | Ведётся ли статистика по всем зарегистрированным инцидентам и используются ли результаты анализа для корректировки политики безопасности? | Нет | Цикл непрерывного улучшения безопасности не работает |
| 6 | Как часто проводятся внутренние и внешние аудиты безопасности? Обновляются ли политики и процедуры на основе результатов этих аудитов? | Не проводятся | Аудит — ключевой инструмент для независимой оценки и улучшений |
